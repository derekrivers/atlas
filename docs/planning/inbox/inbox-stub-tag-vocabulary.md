title: "Free-form extractor tags make lessons unreachable and pattern detection unable to fire: anchor tags to the source ticket's vocabulary"
objective: "The extractor draws a lesson's tags from its source ticket's own tags and component, with a bounded allowance for novel tags, so every lesson is retrievable by construction for work like the work it came from, and lessons from similarly-tagged tickets cluster densely enough for pattern detection to function."
context: "Live finding, 2026-07-17, measured against the first real corpus (18 backfilled DRAFT lessons). `atlas/learning/prompts/lesson-extractor-v1.0.0.md.j2` lists `tags` as an allowed output key with NO vocabulary guidance of any kind — no instruction to reuse the ticket's tags, no controlled list, nothing. The model invents tags freely, and two distinct failures follow. FAILURE 1, reachability: retrieval matches a lesson only when its tags intersect the ticket's facets (`ticket.tags` + `ticket_type`, per `atlas/context/lesson_retrieval.py`). Lesson c629cfb5 ('Degraded sync push must not advance the cursor') carries tags `sync, linear, cursor, pack-embed, degraded-push, idempotency, repair, dirty-input, adr-0006` and intersects ZERO tickets in the store — it could be promoted at confidence 1.0 and reach nobody, forever. Others are near-unreachable: 4b2db698 matches 1 ticket, b1c4282e matches 2, 04fb6342 (the rebase discipline) matches 3. Meanwhile generic tags over-match: `planning` hits 39 tickets, `cli` hits 29. The distribution is bimodal and nobody designed it that way. FAILURE 2, pattern detection: `detect_pattern_candidates` requires the same tag across >=3 DRAFT-or-ACTIVE FAILURE_PATTERN lessons (`PATTERN_THRESHOLD`). Across the 9 failure-pattern lessons in the corpus, the maximum recurrence of any tag is 2 (`deduplication`, `reconciler`, `tech-debt`, `linear-sync`, `inbox-stubs`, `retirement` each reach exactly 2). `atlas lessons report` prints 'No pattern candidates detected' — and will do so indefinitely regardless of how many lessons accumulate, because ~110 distinct tags across 18 lessons means three extractions will essentially never agree on a term. That is a design ceiling, not a null result. Both failures share one root cause: a lesson's tags describe the model's free association rather than the work the lesson came from. Operator ruling OP-A(a), 2026-07-17: fix it at the prompt — rejected alternatives recorded: a controlled vocabulary enforced at write (brittle; needs a vocabulary source of truth that does not exist), widening the matching rule to component/title tokens (helps reachability only, changes retrieval semantics), and lowering PATTERN_THRESHOLD 3->2 (arbitrary; fixes neither reachability nor the entropy). Pre-ruled decisions: D-1 a new versioned prompt template `lesson-extractor-v1.1.0.md.j2`; the version constant moves to it and v1.0.0 is retained on disk as the record of what produced the existing corpus. D-2 the prompt instructs: draw tags primarily from the source ticket's `tags` and `component`, which are supplied in the rendered prompt; at most 2 novel tags may be added when the lesson genuinely concerns something the ticket's vocabulary does not name. D-3 the ticket's tags and component are rendered INTO the prompt explicitly — the model cannot reuse a vocabulary it was never shown; this is the mechanical half of the fix and the testable one. D-4 acceptance is structural, not behavioural: assert the rendered prompt contains the source ticket's tags, its component, and the tag-guidance instruction. An LLM's output distribution cannot be pinned deterministically and this ticket will not pretend otherwise; the live check is the operator's, post-merge. D-5 PATTERN_THRESHOLD is unchanged at 3 — this ticket makes the threshold reachable rather than moving the goalposts. D-6 the existing 18 lessons are NOT retagged by this ticket: re-extraction costs model spend and the attempt cursor blocks it without `--force`. Operator ruling of record: they are retagged by hand at promotion via the documented edit-then-promote path, since the operator reads each lesson at the gate anyway. D-7 learning-system.md's extraction section states the tag-vocabulary rule so the constraint is documented where the design lives, not only in a template."
