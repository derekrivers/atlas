Root cause: `atlas/linear/ownership.py` pins `TicketStatus.REJECTED: frozenset({'cancelled'})` (British), while the live board reports `canceled` (US) for its Canceled state and `duplicate` for its Duplicate state. Why the 1885-test suite is green while the board fails: `tests/test_preflight.py` builds its fixtures as `WorkflowState('state-canceled', 'Canceled', 'cancelled')` and `WorkflowState('state-duplicate', 'Duplicate', 'cancelled')` — every terminal-negative state faked to the spelling the code demands — while `tests/test_pm_sync.py:105` uses `type='canceled'`. Two test files disagree about the external system's vocabulary and the preflight suite asserts the fiction. This gap was flagged during ATLAS-148 and carried; ATLAS-155 scoped the fix and was REJECTED before implementation. Its extracted lesson (af5799f7, promoted ACTIVE at confidence 1.0 on 2026-07-17) states the generalisation that came true: validation allowlists hardcoding a single spelling variant of an external system's enum will silently diverge from the live system and block dependent workflows; known gaps flagged for follow-up but not resolved accumulate into blocking defects. Do not widen any other status's row. D-2 the fixture lie is the root cause and is fixed in the same change: `tests/test_preflight.py` fixtures assert the LIVE spellings, not the convenient ones; if a fixture and the live board disagree, the fixture is wrong. D-3 the two test files share one vocabulary — reconcile `test_pm_sync.py` and `test_preflight.py` on the same type strings. D-4 `_ACCEPTED_TYPES` remains a contradiction check, not a 1:1 oracle (its existing docstring contract is unchanged); this ticket widens one row, it does not redesign the mechanism. D-5 the `Known gap, flagged for follow-up` paragraph in `pm-engine-and-linear-sync.md` is resolved in this change, documenting the admitted spellings and why. D-6 REJECTED is NOT added to `_WRITTEN_STATUSES` — Atlas never writes it (ADR-0006 status direction); C3's scope is unchanged."
